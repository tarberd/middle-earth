# Functional Rust Idioms and Pure Core Architecture

Onehost mandates an expression-oriented, functional programming paradigm in Rust centered on a Pure Core / Imperative Shell architecture. Domain logic, XML transformations, and reconciliation planning are modeled as pure, stateless functions producing immutable data structures (`OnehostPlan`, `DomainXmlElement`). Side effects are strictly isolated: hypervisor interactions sit behind the `Hypervisor` boundary port (implemented by `VirshHypervisor` in production and an in-memory `FakeHypervisor` in tests), while storage manipulations directly utilize the local-substitutable `QemuImgStorage` toolchain against temporary directories, eliminating mockable traits and interaction-recording spies. Code across all targets enforces total error handling via `thiserror` enums (forbidding `unwrap()` and `panic!`), replaces both imperative `for`/`while` loops and side-effecting `for_each`/`try_for_each` calls with value-producing iterator combinators (`map`, `filter`, `fold`, `try_fold`, `collect`) and immutable functional builders, and forbids dead code or underscore-prefixed unused identifiers (`_field`, `_param`, `_var`).
