# Functional Rust Idioms and Pure Core Architecture

Onehost mandates an expression-oriented, functional programming paradigm in Rust centered on a Pure Core / Imperative Shell architecture. Domain logic, XML transformations, and reconciliation planning are modeled as pure, stateless functions producing immutable data structures (`OnehostPlan`, `DomainXmlElement`). Side effects are strictly isolated: hypervisor interactions sit behind the `Hypervisor` boundary port (implemented by `VirshHypervisor` in production and an in-memory `FakeHypervisor` in tests), while storage manipulations directly utilize the local-substitutable `QemuImgStorage` toolchain against temporary directories, eliminating mockable traits and interaction-recording spies. Production code enforces total error handling via `thiserror` enums (forbidding `unwrap()` and `panic!`), replacing imperative mutation loops with declarative iterator combinators (`map`, `filter`, `try_fold`) and immutable functional builders.
