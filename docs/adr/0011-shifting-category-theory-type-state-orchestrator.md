# Category-Theory Type-State Machine for Agentic Orchestration

To eliminate token ballooning, context rot, and unverified model drift across long-running development loops, autonomous agent orchestration is decoupled into an out-of-process, zero-dependency Type-State machine library named `shifting` in `packages/shifting`. The core engine models transitions mathematically using Category Theory primitives: unconditional transformations as morphisms (`Step<In, Out>`), conditional decision points as pure coproduct morphisms (`Branch<In, Left, Right>` yielding zero-dependency `Either<L, R>`), canonical coproduct injections (`either::IntoLeft`, `either::IntoRight`), coproduct identity (`either::Identity`, `either::id()`), sequential identity morphisms (`step::Identity<T>`, `step::id()`), direct cascading branch-to-branch composition (`branch_both`, `branch_left`, `branch_right`), fully heterogeneous error typing across sequential transitions and branch cascades (`Either<ErrA, ErrB>`), and iterative execution driven by control-flow sum types (`LoopFlow<State, Terminal>`) with ergonomic collapses to `Option`. Execution boundaries are bridged via Unix STDIN/STDOUT stream piping through conventional scripts in `.shifting/` (`plan.sh`, `work.sh`, `verify.sh`, `commit.sh`, `rollback.sh`), ensuring non-zero verification failures deterministically roll back working tree state before code can ever land.
